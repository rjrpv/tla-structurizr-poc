Code → DSL delta, advertised in the PR

When a PR changes code/reservation/, CI regenerates the model, diffs it against the committed DSL, and posts the delta. You review what changed in the architecture, not the code.

The diff is the unit of review. A green line is a new piece of architecture; a red line is a change that breaks the intended model.

CI can gate on violations (red) while allowing expected additions (green) once the intended model is updated in the same PR — that's your intellectual control.

Everything above is plain Python + open source: a small AST/import parser (or pydeps for the raw graph), a committed intended DSL, difflib for the delta, and the GitHub API to post the comment. No paid tooling, no lock-in — the model is a text file you own.
